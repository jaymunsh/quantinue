## 1. 결론

현재 덱은 **기술적으로 발표 가능한 상태**다.

- HTML 본편 19장이 네 화면 크기에서 모두 정상 렌더링됐다.
- 잘림·겹침·깨진 이미지·한글 글리프 누락·브라우저 오류는 발견되지 않았다.
- 키보드와 화면 클릭 이동, 영상 재생, 슬라이드 이탈 시 영상 자동 정지가 정상이다.
- 영상은 120.3초이며 디코딩 오류가 없다.
- 최신 PDF는 19페이지이고 HTML과 장수가 일치한다.
- 이전 `codex_추천개선안.md`의 핵심 문제였던 깔때기 설명, 테스트 합계,
  중복 방지 근거, SPY 기간 표기, 구형 PDF 문제는 반영됐다.
- `codex_추천개선안2.md`에서 다룬 후반부 두 장도 “두 스위치”와 정석 회고
  구조로 다시 정리돼 이전보다 목적이 분명해졌다.

다만 **완료와 발표 성공은 아직 같지 않다.** 현재 가장 큰 위험은 화면 결함이
아니라 다음 세 가지다.

1. **19장을 12분 30초에 전달할 수 있는지 리허설로 검증되지 않았다.**
2. **오래된 계획·원고 문서가 최신 19장 정본과 충돌한다.**
3. **기술 설명이 많은 8·9·11·15·16·17번은 프로젝터 거리에서 작게 보일 수 있다.**

따라서 판정은 **“발표 가능, 리허설과 정본 정리 후 최종 확정”**이다.

## 3. 이전 개선안 반영 여부

### 3-1. 반영 완료

#### 깔때기 설명

현재 13번은 `2,000 → 222 → 342 → 323 → 62`가 단순 감소가 아니라는 점을
`판단에서 한 번 늘고, 검증부터 줄어듭니다`라고 먼저 설명한다
(`slides/index.html:769-777`).

또한 다음을 명시한다.

- 후보 222건은 `상위 20 + 보유 종목`의 7거래일 누적
- 판단 342건은 두 성향이 각각 판단해 후보보다 증가
- 중복 방지는 `계좌+시그널` 기반 주문 고유 키와 DB `UNIQUE` 제약
- 테스트는 `994 = 유닛·웹 804 + 통합 190`

이제 수치 자체와 설명의 논리가 맞는다.

#### SPY 기간

14번은 운용과 SPY의 종료일이 다르다는 점을 숨기지 않는다
(`slides/index.html:789-828`).

- 운용 합산: 7거래일, 07-28까지, −0.34%
- SPY: 6거래일, 07-27까지, −0.44%
- 대본: 우열 비교가 아니라 참고선이라고 명시

동기간 성과 비교처럼 보였던 이전 문제는 해결됐다.

#### 테스트 합계와 비평가 분모

- 테스트: 994건
- 비평가 반려: 검토 323건 중 57건, 18%
- 기계 게이트 84%와 LLM 16%: 검증 323건 기준

16%와 18%가 서로 다른 지표임을 화면에서 구분할 수 있다
(`slides/index.html:673-689`).

#### PDF

`slides/quantinue-final.pdf`는 2026-07-28 17:47 생성, 19페이지,
페이지 크기 1200×675.12pt다. 현재 HTML 19장과 장수가 일치한다.

#### 16·17번 후반부

이전 보고서의 핵심 제안이 방향상 반영됐다.

- 16번은 `실제 주문 OFF`와 `클라우드 이전 보류`를 각각 조건부 결정으로 표현한다.
- 17번은 `계속할 것 / 아쉬웠던 것 / 다시 한다면`으로 역할이 분리된다.
- AWS 세부 사양은 한 줄로 줄었고, 회고는 실제 숫자와 사건에 연결된다.

두 장 모두 이전의 평평한 카드 나열보다 발표자가 말할 결론이 명확하다.

### 3-2. 추가로 남은 점

#### SPY 차트의 접근성 문구

화면 문구는 6거래일이라고 바로잡았지만 SVG의 `aria-label`은 여전히
`운용 계좌 합산과 SPY의 7거래일 지수 비교`라고 되어 있다
(`slides/index.html:800`).

시각 발표에는 영향이 없지만, 문서의 자기 일관성을 위해 향후에는
`운용 7거래일과 SPY 6거래일 참고선`처럼 맞추는 편이 정확하다.

## 4. 서사와 구성 검토

### 잘된 흐름

현재 19장은 다음 흐름이 자연스럽다.

`이름과 문제 → 한 바퀴 검증 → 3층 해법 → 실제 구조와 코드 역할 → 하루 실행
→ AI 통제 → 페르소나 → 영상 → 원장 기록 → 운영 사건 → 남겨 둔 스위치
→ 회고 → 선언`

특히 잘된 연결은 다음과 같다.

- 5번의 1차 경험이 6번의 3층 구조를 필요하게 만든다.
- 6번의 그림을 7·8·9번이 구조·역할·시간 순으로 풀어 준다.
- 12번 영상 뒤에 13·14번 실측 기록이 바로 이어져 “데모만 잘 만든 것”이라는
  의심을 줄인다.
- 15번 실제 장애 사건이 16번 클라우드 보류 판단의 근거가 된다.
- 18번은 수익률이 아니라 과정의 연속성을 주장하며 전체 발표를 닫는다.

### 개선 아이디어 1 — 7·8·9번 기술 3연장의 시간 통제

세 장 모두 내용은 좋지만 연속해서 들으면 청중에게는 가장 무거운 구간이다.
화면을 더 고치기보다 발표 문장을 제한하는 편이 안전하다.

- 7번: `들어온다 / 판단한다 / 남는다 / 바깥에서 감시한다`만 말한다.
- 8번: 여섯 역할을 모두 읽지 말고 `AI는 ③·④ 두 자리뿐`을 중심으로 말한다.
- 9번: 잡 이름을 읽지 말고 `13시 하루 체인 + 22:30 1분 방어`만 짚는다.

세 장의 목표 시간을 합쳐 **2분 10초 안쪽**으로 잡는 것을 권한다.

### 개선 아이디어 2 — 반복되는 상단 번호를 챕터라고 명확히 하기

상단 번호는 실제 장 번호가 아니라 챕터 번호다.

`04`가 6~9번에서, `05`가 10~11번에서, `07`과 `08`이 각각 두 번 반복된다.
우하단 HUD에는 실제 페이지 `08 / 19`가 별도로 표시되므로 기능상 문제는 없다.
다만 청중이나 발표자가 상단 숫자를 장 번호로 받아들이면 대본의 “8화면”과
혼동할 수 있다.

향후 수정한다면 두 방식 중 하나가 좋다.

- 상단 숫자 앞에 `CH.`를 붙여 챕터임을 명시
- 상단은 실제 페이지 번호로 바꾸고 챕터 이름만 유지

발표 직전에는 굳이 고치지 않아도 되지만, 대본에서는 반드시 우하단 페이지
기준으로 이동해야 한다.

### 개선 아이디어 3 — 17번 회고는 읽지 말고 선택해서 말하기

17번은 내용은 탄탄하지만 7개 항목이 한 장에 있다. 발표자가 전부 읽으면
회고가 길어지고 마무리 힘이 약해진다.

권장 낭독 우선순위:

1. 계속할 것: `모든 걸 AI에 맡기지 않은 것`
2. 아쉬움: `실제 운용 7거래일`
3. 다시 한다면: `기록은 첫날부터`
4. 나머지는 화면에 남겨 두고 생략

## 5. 화면과 투사 가독성

### 전반 판정

1600×900과 1280×720에서는 전 장의 조판이 안정적이다.
375×667·768×1024에서도 16:9 무대가 중앙 축소되어 잘리지는 않는다.
세로 화면에서 글자가 작아지는 것은 반응형 문서가 아니라
**발표용 고정 캔버스**라는 현재 설계의 의도와 일치한다.

### 집중 확인할 장

| 장 | 이유 | 발표 전 확인 방법 |

| 7 | 모듈·테이블·포트 식별자가 작다 | 식별자는 읽히지 않아도 큰 3영역이 보이면 통과 |
| 8 | 6개 역할 카드와 보조 수치가 조밀하다 | 발표자가 카드 문장을 읽지 않아도 이해되는지 확인 |

### 글꼴 이식성

한글은 `Apple SD Gothic Neo`, `Pretendard`, 시스템 폰트 순서이고 모노 폰트는
`SFMono`, `Menlo`, `JetBrains Mono` 등에 의존한다
(`slides/index.html:29-30`). Mac에서는 현재 캡처와 같이 안정적이지만,
Windows나 다른 발표 PC에서는 글자 폭이 달라질 수 있다.

가장 안전한 운용은 다음과 같다.

1. 발표에 쓸 동일 Mac에서 HTML을 실행한다.
2. 다른 PC를 써야 하면 PDF를 1차 백업으로 둔다.
3. 장기적으로는 Pretendard와 모노 폰트를 로컬 자산으로 포함한다.

## 8. 내용상 말조심할 지점

### 수익률

14번의 메시지는 현재처럼 “우열 비교가 아닌 참고선”으로 유지해야 한다.
종료일이 다르므로 `시장보다 잘했다`는 표현은 쓰지 않는 것이 맞다.

### 공시·뉴스

수집·정규화 1.9만 건과 판단 입력 연결은 다른 문제다. 대본의 가드대로
`수집은 돌지만 판단 연결은 얕다`고 말해야 한다. “뉴스와 공시를 보고
거래했다”로 단순화하면 6번과 17번의 정직한 설명이 무너진다.

### 재현성

342건 모두 근거가 남았다는 것과 342건 모두 모델·프롬프트까지 재현 가능하다는
것은 다르다. 재현 기록은 234/342이고 초기 102건은 도입 전이라는 현재 대본을
유지해야 한다.

### 실제 주문·정책·인가

16번은 법률 결론을 선언하는 장이 아니라 **켜기 전 검토 게이트를 보여 주는 장**이다.
대본처럼 “검토 목록으로 관리한다”, “사람 승인 단계를 넣는 설계까지 정했다”까지만
말하는 것이 안전하다. 이 검증에서는 정책·법률 주장을 외부 원문과 다시 대조하지 않았다.

## 9. 반드시 유지할 장점

- 초록은 기계·규칙, 보라는 AI, 주황은 경고·방어라는 의미색이 일관된다.
- 숫자 장마다 원장·설정·문서 좌표를 하단에 붙인 방식이 발표의 주장과 맞는다.
- “AI를 많이 썼다”가 아니라 “쓸 곳을 고르고 통제했다”는 메시지가 차별화된다.
- 데모와 실제 운영 기록을 구분해 과장하지 않는다.
- 7거래일 수익률을 성과로 포장하지 않고 기록 체계의 증거로 사용한다.
- 모니터링 실패, 재현성 도입 시점, 상류 데이터 연결 부족을 숨기지 않는다.
- 영상 실패 시 구성표가 대신 보이는 폴백이 있다.
- 마지막 두 장은 밀도를 낮춰 Q&A로 넘어가는 호흡이 좋다.
