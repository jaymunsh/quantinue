**남은 것은 13:05 요약을 받는 일뿐이다.** 그날 슬롯이 13:00에 열리고
13:05에 `daily_summary`가 새 형식으로 한 통 보낸다:

```
✅ 2026-07-28 슬롯 · 잡 14/14 성공 · 신규 매수 N건
방어선 N건 · AI 지출 $X.XX          ← 이 줄이 새로 붙는다
```

그게 오면 아래 2번의 텔레그램 캡처를 뜬다.

⚠️ **재기동 절차 기록** — 다시 할 일이 생기면 이 순서다. `kill`은 에이전트
자동 승인 밖이라 **사용자가 직접** 돌려야 하고, 기동은 에이전트가 할 수 있다.

```bash
# ① 사용자가 실행 (PID는 app-v2/.runtime/observation-owner.lock/pid 에서 확인)
cd app-v2 && kill -TERM <PID> && while kill -0 <PID> 2>/dev/null; do sleep 1; done
# ② 에이전트가 실행 가능
cd app-v2 && (nohup ./scripts/run_observation.sh >/dev/null 2>&1 &) ; sleep 14
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8020/login   # 200이면 성공
```

**정규장(22:30~05:00 KST) 중에는 재기동하지 않는다.** 1분 방어가 도는
중이고 그게 "지금 켜져 있는" 유일한 기능이다. 잡이 `running`일 때도 안 된다.
