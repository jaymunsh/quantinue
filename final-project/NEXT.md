## ⏰ 1. 텔레그램 알림 배포 — **오늘 13:00 KST까지** ★ 가장 급함

**아직 안 올라갔다.** 운영 8020은 07-27 18:48에 뜬 프로세스가 그대로 돌고
있고(PID **90859**), 알림 코드는 07-28 00:07 커밋이라 **옛 코드**다.

### 왜 13:00이 마감인가

뉴욕 자정 = 서울 13:00이라 **13:00에 새 슬롯이 열리고 13:05에
`daily_summary`가 텔레그램 한 통을 보낸다**(07-27 발송 로그 `04:05:53Z`
= 13:05 KST로 확인). 그 전에 올려야 **오늘 13:05 요약이 새 형식으로
나가고, 그게 곧 슬라이드 6에 넣을 캡처**가 된다.

```
05:00 장 마감 ──── 지금(08:40) ──── 안전한 재기동 창 ──── 13:00 새 슬롯 · 13:05 요약
```

**지금은 안전하다** — 장 마감(`market_closed` 확인), 도는 잡 0개.

### 어떻게

`kill`은 에이전트 자동 승인 밖이라 **사용자가 직접 실행해야 한다.**
아래 두 줄을 `!` 로 돌리게 안내할 것:

```bash
cd /Users/sunghyuk/Documents/ClaudeCode/quantinue-v2/app-v2 && kill -TERM 90859 && while kill -0 90859 2>/dev/null; do sleep 1; done; echo 정지완료
```
```bash
cd /Users/sunghyuk/Documents/ClaudeCode/quantinue-v2/app-v2 && (nohup ./scripts/run_observation.sh >/dev/null 2>&1 &) ; sleep 12; curl -s -o /dev/null -w '8020: %{http_code}\n' http://127.0.0.1:8020/login
```

> PID는 바뀔 수 있다. 확인: `cat app-v2/.runtime/observation-owner.lock/pid`

**배포는 재기동이 전부다** — 코드는 이미 디스크에 있다. 재기동 뒤
`/api/runtime/status`와 프로세스 기동 시각으로 새 코드가 올라갔는지 검증할 것.

## 3. 리허설 — 아직 한 번도 안 했다


`P`로 연 **발표자 창**에 현재 노트·다음 장 제목·경과 시간이 뜬다.

그대로 나간다. 리허설에서 혼자 볼 때만 쓴다.
