# Codex 추천 개선안 2 — 발표 후반부 슬라이드

검토일: 2026-07-28  
대상: `slides/index.html`의 「일부러 남겨 둔 두 가지」, 「돌아보며 — 배운 것과 아쉬운 것」

> 검토 도중 앞쪽에 슬라이드가 추가되어 장 번호가 한 칸 밀렸다. 따라서 이 문서는 장 번호보다 **슬라이드 제목을 기준**으로 작성한다.

## 1. 전체 진단

두 슬라이드는 내용이 약한 것이 아니라 **정보 위계가 평평한 것**이 문제다.

- 앞 장의 모니터링 사건은 실제 화면과 시간 기록이 있어 에너지가 강하다.
- 「일부러 남겨 둔 두 가지」는 갑자기 AWS 체크리스트처럼 보인다.
- 「돌아보며」는 네 카드가 모두 같은 무게라 가장 중요한 결론이 묻힌다.
- 발표 마지막 선언문 직전에 긴 문장을 읽어야 해 서사의 속도가 떨어진다.

개선 방향은 다음과 같다.

1. 「남겨 둔 것」은 기술 사양이 아니라 **의도적인 보류 결정과 해제 조건**을 보여 준다.
2. 「돌아보며」는 네 가지를 나열하지 않고 **검증된 세 원칙과 남은 한 연결**로 재구성한다.
3. 본문을 줄이고 핵심 숫자를 시각적 증거로 사용한다.
4. 현재 덱의 색 의미를 유지한다.
   - 초록: 검증 완료·결정론
   - 보라: AI 판단
   - 황토: 보류·위험·미해결

## 2. 「일부러 남겨 둔 두 가지」 개선안

### 현재 화면의 문제

- 핵심은 “두 기능을 왜 켜지 않았는가”인데 오른쪽 AWS 표가 가장 큰 면적을 차지한다.
- 실제 주문과 클라우드 이전은 서로 다른 결정인데, AWS 상세 정보가 클라우드 쪽에만 몰려 균형이 깨진다.
- 인스턴스·SSM·SSH·`pg_dump`·`restart=always`는 본편보다 질문 대응용 정보에 가깝다.
- 앞 슬라이드에서 노트북 절전 사건을 이미 설명했는데 클라우드 카드에서 다시 반복한다.
- 연속된 흰색 카드 때문에 “중요한 의사결정”보다 일반 설명 화면처럼 보인다.

### 추천 제목

> **마지막 두 스위치는 검증 뒤에 켭니다**

조금 더 서사적으로 표현한다면 다음 문장도 가능하다.

> **운영 한계는 드러났지만, 검증 순서는 바꾸지 않았습니다**

### 추천 레이아웃

```text
┌ 실제 주문 · OFF ─────────────┐  ┌ 클라우드 이전 · DEFERRED ────────┐
│ 지금 잠근 이유                  │  │ 지금 보류한 이유                    │
│ 무인 검증 전에는 자금을 움직이지 않음 │  │ 이전 자체가 기능 검증을 빠르게 하지 않음 │
│                               │  │                                  │
│ 켜는 조건                      │  │ 착수 조건                           │
│ 무인 검증 통과                  │  │ 상시 운영 필요성과 검증 완료 확인        │
└───────────────────────────┘  └──────────────────────────────┘

준비 완료  t4g.small · SSM · SSH 터널 · pg_dump · restart=always
```

### 화면에 남길 정보

#### 실제 주문

- 상태: `OFF`
- 이유: 무인 검증 전에는 실제 자금을 움직이지 않는다.
- 해제 조건: 무인 검증 통과

#### 클라우드 이전

- 상태: `DEFERRED`
- 이유: 서버 이전이 현재의 기능 검증을 빠르게 하지는 않는다.
- 착수 조건: 상시 운영 필요성과 기능 검증 완료

#### 준비 근거

기존 5행 표는 아래처럼 한 줄로 축약한다.

> `t4g.small · 월 $20~40 · SSM 주입 · SSH 터널 · pg_dump · restart=always`

상세 설명은 발표 대본이나 `자주나올질문.md`로 이동하는 편이 적합하다.

### 추천 발표 멘트

> 운영 한계는 실제로 드러났지만, 그렇다고 검증 순서를 바꾸지는 않았습니다. 실제 주문과 클라우드는 각각 켜는 조건을 정해 두고 보류했습니다. 주문은 무인 검증 뒤에, 클라우드는 상시 운영 필요성과 기능 검증이 확인된 뒤에 착수합니다. 필요한 이전 방식은 이미 조사해 두었습니다.

## 3. 「돌아보며 — 배운 것과 아쉬운 것」 개선안

### 현재 화면의 문제

- “배운 것 3개 + 아쉬운 것 1개”라는 비대칭 메시지를 네 개의 동일한 카드로 표현한다.
- 원칙과 증거 숫자가 본문 속 굵은 글씨에 묻힌다.
- 1280×720 프로젝터 화면에서는 네 열의 본문이 작고 조밀해진다.
- 네 카드를 모두 읽어야 해서 청중이 기억할 단일 결론이 없다.
- `뉴스·공시 채점이 판단에 거의 닿지 않았다`는 설명이 다음 장의 `판단 → 검토 → 체결 → 기록이 끊기지 않는다`와 모순처럼 들릴 수 있다.

### 추천 제목

> **통제는 증명했고, 연결은 남았습니다**

대안:

> **결국 AI 시스템의 품질은 모델보다 과정에서 갈렸습니다**

### 추천 레이아웃

```text
검증된 세 가지 원칙                         아직 끊긴 상류 연결

01 예산 통제          $0.53 / 4일          뉴스·공시 1.9만여 건
   모든 호출은 예산 경계를 통과                  ↓
                                            채점
02 판단 재현          342건 근거                ── × ──
   모델·프롬프트·입력값 기록                     ↓
                                            실제 판단 한 자릿수
03 협업 인계          세션이 바뀌어도
   금지선과 검증 절차 유지                  다음 단계: 채점 → 판단 연결
```

### 왼쪽 — 검증된 세 원칙

#### 01. 예산 통제

- 원칙: AI는 기능이 아니라 통제 대상이다.
- 근거: 모든 호출이 예산 경계를 통과한다.
- 숫자: `4일 $0.53`

#### 02. 판단 재현

- 원칙: 재현할 수 없는 판단은 믿지 않는다.
- 근거: 모델·프롬프트 버전·입력값을 함께 기록한다.
- 숫자: `판단 342건 모두 근거 보존 · 234건 재현`

#### 03. 협업 인계

- 원칙: AI와 개발하는 과정에도 인수인계 설계가 필요하다.
- 근거: 세션이 바뀌어도 금지선과 검증 절차를 유지한다.

### 오른쪽 — 아직 끊긴 한 연결

황토색 단일 패널로 다음 내용을 보여 준다.

> **아직 끊긴 상류 연결**  
> 뉴스·공시 → 채점 ──×──→ 실제 판단  
> 수집 약 1.9만 건 · 판단 반영 한 자릿수  
> 다음 단계의 첫 항목: 채점 결과를 실제 판단에 연결

여기서 반드시 `상류 연결`이라고 표현한다. 그래야 다음 장이 주장하는 아래의 완성된 실행 구간과 구분된다.

> 판단 → 검토 → 체결 → 기록

### 추천 발표 멘트

> 실제로 돌려보니 세 가지 원칙이 남았습니다. AI 호출은 예산으로 통제해야 하고, 판단은 다시 재현할 수 있어야 하며, AI와 개발하는 과정도 문서로 인수인계돼야 합니다. 반면 아직 끊긴 구간도 있습니다. 뉴스와 공시는 많이 모았지만 그 채점이 실제 판단에 닿은 사례는 한 자릿수였습니다. 이 상류 연결이 다음 단계의 첫 검증 항목입니다.

## 4. 두 장의 서사 연결

발표 후반부는 다음 흐름으로 정리하는 것이 가장 자연스럽다.

```text
운영 증거
  ↓
켜지 않은 기능에도 명확한 조건이 있다
  ↓
통제는 검증됐고 데이터 연결은 남았다
  ↓
그래서 수익률보다 판단 → 검토 → 체결 → 기록을 주장한다
```

각 슬라이드의 역할은 다음처럼 분리한다.

| 슬라이드 | 역할 |
|---|---|
| 모니터링 3층 | 실제 운영 증거와 사건 |
| 마지막 두 스위치 | 의도적인 보류 결정과 해제 조건 |
| 통제는 증명했고, 연결은 남았다 | 검증된 원칙과 남은 한계 |
| 마무리 선언 | Quantinue가 최종적으로 주장하는 가치 |

## 5. 최소 수정안

구조를 크게 바꾸기 어렵다면 최소한 아래 항목만 적용해도 효과가 있다.

### 「일부러 남겨 둔 두 가지」

- AWS 5행 표를 한 줄짜리 준비 근거로 축약한다.
- 두 카드에 `현재 상태`와 `켜는 조건`을 추가한다.
- 노트북 절전 사건의 반복 설명을 제거한다.
- 제목을 결과형 문장으로 바꾼다.

### 「돌아보며」

- 첫 세 카드를 하나의 넓은 `검증된 세 원칙` 영역으로 묶는다.
- 아쉬운 점만 별도의 황토색 패널로 크게 분리한다.
- `$0.53`, `342건`, `234건`, `한 자릿수`를 본문이 아닌 큰 숫자로 노출한다.
- `뉴스·공시 → 채점 → 판단`의 끊긴 지점을 도식으로 표현한다.

## 6. 유지할 요소

- 실제 수치와 한계를 숨기지 않는 태도
- 하단 원장·근거 바
- 초록·보라·황토의 제한된 색 체계
- “미완성”을 변명하지 않고 다음 검증 조건으로 연결하는 서사
- 마지막 장의 `판단 → 검토 → 체결 → 기록` 선언
